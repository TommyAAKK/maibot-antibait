# AI八股拦截 · maibot-antibait

> 让麦麦别再说 AI 腔。拦截 AI 八股、附和服软腔和结构残留，命中后打回 replyer 重生成一次，并在两次结果中择优发出。

## 这个插件解决什么

大语言模型说话有一股味道：爱总结、爱对仗、爱"作为 AI"、爱把工具调用痕迹一起说出来。
群聊里这种话一眼就被认出不是人说的。

本插件挂在 MaiBot 的 `maisaka.replyer.after_response` 钩子上，回复**发出之前**过一遍体检：

```
replyer 生成
    ↓
上下文赦免（玩梗 / 复读 / 回答问题 → 人也会这么说，放过）
    ↓
规则体检（三档规则 + 序列特征）
    ↓
命中 → 打回重生成一次 → 比较两次结果 → 择优发出
    ↓
未命中 → 机械净化（能零成本改好就改）→ 发出
```

三条设计原则：

1. **只修 AI 味，不改人设。** 口癖、语气词、称呼这些是 bot 的性格，不算八股。
2. **宁可漏赦，不可错赦。** 误杀一次比漏过一次伤害大得多。
3. **先零成本，再花模型。** 能机械净化直接的就不重生成。

## 快速开始

```bash
# 1. 放进插件目录，不要多套一层
cp -r maibot-antibait  <MaiBot>/plugins/antibait

# 2. 确认结构
<MaiBot>/plugins/antibait/_manifest.json
<MaiBot>/plugins/antibait/plugin.py
```

**不需要重启 MaiBot。** Runner 监听插件目录里的 `*.py` 和 `_manifest.json`，
拷进去它会自己重扫重载，日志出现 `antibait 已加载（dry_run=True）` 就成了。

装好后先**保持 `dry_run = true` 跑几天**，等监控数据够了你再决定什么时候真拦。

也可以直接在 WebUI 插件市场里搜索安装。

### 依赖

- **MaiBot 1.3.x**（实测于 1.3.18）
- **maibot-plugin-sdk ≥ 2.9**（本插件按 2.15.0 的 API 编写）
- 不需要任何第三方 Python 包

## 它是怎么判的

### 三档规则

**A 档 · 硬规则**（命中即打回，记 100 分）

| 类别 | 例子 |
|---|---|
| 总结腔 | `总的来说` `综上所述` `总而言之` |
| 过渡腔 | `值得注意的是` `更重要的是` `与此同时` |
| 自曝身份 | `作为一个AI` `我是一个语言模型` |
| 结尾腔 | `希望对你有所帮助` `有问题随时问我` |
| 开头腔 | `这是一个很好的问题` |
| 对仗腔 | `不是…，而是…` `不仅…，更…` `看似…实则…` `与其说…不如说…` |
| 三段式 | `首先…其次…最后` 齐活 |
| 极端标点 | emoji ≥5 字符／颜文字 ≥3／连续感叹号 ≥4 组（**按密度判**，见下） |
| 结构残留 | `<message …>` `msg_id=` `[图片：…]` `[glass-meme-lookup]` 这类工具痕迹 |

**B 档 · 软规则**（计分，≥ 3.0 打回）

| 类别 | 分值 | 说明 |
|---|---|---|
| 总结词（本质上／说到底／归根结底／毋庸置疑） | 1.0／条 | 合计封顶 2.0 |
| 颜文字 | 0.3 | 可调 `kaomoji_weight` |
| emoji | 1.0 | |
| 破折号 `——` ／连续感叹号 | 0.5 | 标点合计封顶 2.0 |
| 排比三连／语气词结尾／反问收尾 | 各 1.0 | |
| 列表化／过长且无口语／连接词堆叠 | 各 1.0 | 长文本豁免，见下 |
| 口癖（soft） | 1.0／条 | 合计封顶 2.0 |

**B+ 档 · 附和服软腔**（各 1.0，不封顶，靠叠加）

| 类别 | 例子 |
|---|---|
| 叠词服软 | `行吧行吧` `行行行` `好好好` `是是是` `算了算了` |
| 认输自贬 | `我菜` `我蠢` `我傻` `我认输` `我服了` |
| 夸对方赢 | `你赢了` `你厉害` `参数党赢了` |
| 句尾附和 | `嗯嗯` `哦哦` `对对`（**必须挂在句末**） |

这类话人也会说，单条最多 2~3 分，单独很少够打回——真正的 AI 味来自**连着说**。

**C 档 · 口癖**：你自己在 `tics.json` 里加的正则，`hard` 直接打回，`soft` 记 1 分。

### 序列特征：跨回复才判得出来的

单条「行行行」是正常附和，连发三条就是机器味。这类特征只能看上一条：

| 特征 | 条件 | 加分 |
|---|---|---|
| 同款颜文字连发 | 本条结尾颜文字与上一条**完全相同** | +1.0 |
| 连续附和服软 | 本条与上一条**都**命中附和服软档 | +1.0 |

插件会记住每个会话最近 5 条**真正发出去**的回复（打回重生成的那些不进历史）。

## 三个容易踩的坑，都处理过了

### 1. 标点类不能重复计分

`（— w —）` 里有两个破折号。如果直接跑标点规则，颜文字 +1、破折号 +1，同一段文字算两次。

解决办法是**先遮蔽、再计分**：

```
原文 → 剥代码块 → 剥行内代码 → 剥 URL → 剥引用行
     → 遮蔽颜文字（含汉字的不算颜文字，交给口癖）
     → 吸收颜文字尾巴的装饰符（✧☆★♪♡…不单独算 emoji）
     → 遮蔽 emoji
     → 只在残渣上跑 破折号 / 感叹号 / 排比 / 语气词 等规则
```

遮蔽后破折号规则根本看不到 `—`，物理上不可能重复。

### 2. 引用和代码块不判

`> 总的来说，这是对的` 和代码块里的「总的来说」都得分 0——
引用别人的话不算自己说八股。

### 3. 长文本不判结构

榜单、教程、周报天生就带列表、长句、对仗。这类内容超过 `long_text_threshold`
（默认 200 字）后，**结构类规则整类跳过**；但"事故类"规则（标签残留、自曝 AI）
任何长度都照查——这跟文风无关，长文里出现一样是 bug。

"堆砌"也按密度判，不是按个数：881 字的周榜里出现 3 个颜文字不叫堆砌。

## 赦免层：打回之前先看语境

同一句「总的来说，这事儿分三步」：

- 没人问你，自己张嘴就来 → 八股，该打回
- 对方刚说「帮我总结一下这几点」→ 按要求办事，打回就是误杀
- 群里正玩梗，你接一句「卧槽笑死😀😁😂🤣😊」→ 人也会这么发

所以打回之前先过一道赦免。四个通道：

| 通道 | 认什么 | 能赦免的范围 |
|---|---|---|
| `echo` | 复读／引用：与群里别人刚说的话高度重合 | 除「不可赦免」外全部 |
| `intent` | 请求意图：上一条在要求总结／分步骤／做对比／解释原因 | 只赦该意图下合理的规则 |
| `meme` | 玩梗／起哄：梗词 ≥2 个，或整句是「哈哈哈」「草」「6」 | 只赦标点表情与口语类 |
| `answer` | 回答问题：上一条是问句，且回复 ≤60 字 | 只赦口语类 |

关键设计：**不是打分凑够就赦，而是这条回复的所有命中码都要被这个语境解释掉。**

所以「玩梗」能赦表情堆砌，但赦不了总结腔；「对方要求总结」能赦总结腔，但赦不了自曝 AI。

### 永远不赦

```python
NEVER_AMNESTY = {"zipu", "jiewei", "kaitou", "extra_hard", "tic_hard", "label_leak"}
```

自曝身份、结尾腔、开头腔、你自定义的硬规则、你标 hard 的口癖、结构残留——
**任何语境都不赦**。这些不是风格问题，是 AI 味本体。

### 防「机器人复读自己」

`echo` 通道会先对复读源本身跑一次检查：**如果那句话本身就被判成八股，跳过不认**。
否则机器人把自己上一轮生成的八股复读一遍，就被当成"人也在这么说"而赦免了。

### 读不到上下文不乱赦

`get_recent` 拿不到就退化成无上下文，只靠句子本身判断，不会因为缺信息就放行。

## 重试与择优

`maisaka.replyer.after_response` 是**顺序**调用的，没法并行生成两份再挑。
生成器每轮直接覆盖 `response`，自己不留旧文本。所以"两次对比择优"只能这么做：

```
第 1 次命中 → 记下原文和分数 → 置 retry=True 打回
第 2 次生成 → 取出旧记录比较
              ├─ 新的干净            → 用新的
              ├─ 新的更脏、旧的没硬伤 → 把 response 改回旧的（回滚）
              └─ 旧的本来就有硬伤     → 保留新的（绝不发硬伤）
```

三条硬规矩：

1. **只重试一次**。`retry_count == 0` 才置 retry，`【重生成约束】`只注入一次。
2. **硬伤永不回滚**。第一份命中硬规则，哪怕软分更低也不回滚。
3. **状态丢了就放行**。插件热重载导致旧记录丢失时，直接采用第二次，不报错。

## 口癖自动生成

`antibait_tics_suggest` 工具：取最近发言 → 调一次模型 → **过校验** → 存草稿。

校验才是重点，模型很爱给 `.*呢.*` 这种，一开就把所有回复拦了：

| 检查 | 规则 |
|---|---|
| 编译 | `re.compile` 不报错 |
| 长度 | ≤ 40 字符 |
| 灾难回溯 | 禁止嵌套量词 `(a+)+`、禁止首尾 `.*` |
| **命中率下限** | ≥ 2%（低于此是偶发噪声） |
| **命中率上限** | ≤ 30%（高于此是正常说话） |
| 去重 | 与已有模式 bigram 相似度 < 0.8 |

那个 2%~30% 的区间是最有价值的一条：一个"口癖"必须**反复出现**但**又不是所有人都在说**。

**生成的候选一律是草稿**，写到 `tics.draft.json`，人工确认后才进 `tics.json`。
绝不写 `config.toml`——Runner 监听那个文件，插件自己写会触发「写入→重载→再写」循环。

## 试运行监控

`dry_run = true` 时不打回、不改写，但**每次命中都会写一行 JSONL**。
默认只记命中的；想算准确的分母就把 `monitor_record_all = true` 打开。

记录长这样：

```json
{"ts":"2026-10-23T14:55:47+08:00","mode":"dry_run","session_id":"...","reply_message_id":"...",
 "request_type":"maisaka.replyer","task_name":"replyer","attempt":1,"retry_count":0,
 "score":100.0,"hard":1,"blocked":true,"decision":"would_retry",
 "rules":[{"code":"duizhang","label":"对仗腔（不是…而是…）","weight":100.0,"hard":true}],
 "text":"这不是技术问题，而是心态问题。","text_len":16,"truncated":false}
```

`decision` 一眼看出每条走到哪了：

| decision | 含义 |
|---|---|
| `pass` | 没命中（仅 `monitor_record_all=true` 时记） |
| `would_retry` | **dry_run 命中**：真实模式这里会打回 |
| `retry` | 真实模式打回了 |
| `scrubbed` | 命中但机械净化改好了，没花模型调用 |
| `amnesty` | 命中但被赦免（`channel`/`why` 说明理由） |
| `pass_second` | 第二次干净，采用第二次 |
| `rollback` | 第二次更脏，已回滚到第一次 |
| `keep_second` | 两次都脏，保留第二次 |

汇总用工具 `antibait_monitor_report`（`top` 控制样例条数，`clear=true` 清空重来）。

文件超过 `monitor_max_bytes` 自动滚成 `.1`；正文默认只存前 500 字。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 插件内部总开关 |
| `dry_run` | `true` | 只记录不拦截，先观察误杀 |
| `max_retries` | `1` | 固定 1 次。别改大 |
| `pick_better` | `true` | 第二次更差时回滚第一次 |
| `soft_threshold` | `3.0` | 软规则打回分数线 |
| `punctuation_cap` | `2.0` | 标点表情类合计上限，**故意低于打回线** |
| `kaomoji_weight` | `0.3` | 单个颜文字的分；设 `1.0` 恢复旧行为 |
| `min_length` | `6` | 短于此长度不检查 |
| `long_text_threshold` | `200` | 超此字数视为产出物，跳过结构类规则 |
| `fucong_enabled` | `true` | 附和服软腔这一档 |
| `sequence_enabled` | `true` | 序列特征（同款颜文字连发／连续服软） |
| `request_types` | `[]` | 只处理这些 `request_type`。**别填 `chat`**——replyer 实际传 `maisaka.replyer` |
| `tics_enabled` | `false` | 启用口癖拦截 |
| `tics_file` | `tics.json` | 口癖库文件名（在 `data_dir` 下） |
| `extra_hard` | `[]` | 追加硬规则正则 |
| `monitor_enabled` | `true` | 每次检查写一行 JSONL |
| `monitor_record_all` | `false` | 连没命中的也记（算分母用，文件会大） |
| `monitor_max_bytes` | `5242880` | 单文件上限 |
| `monitor_max_text` | `500` | 记录里正文最多存多少字 |
| `amnesty_enabled` | `true` | 打回前先判断语境 |
| `amnesty_use_context` | `true` | 读最近消息做判断 |
| `amnesty_context_limit` | `8` | 读最近几条消息 |
| `amnesty_echo_jaccard` | `0.75` | 复读判定相似度 |
| `amnesty_meme_min_marks` | `2` | 至少几个梗词才算玩梗 |
| `amnesty_answer_max_len` | `60` | 短答上限 |
| `amnesty_llm` | `false` | 本地判断不了时调一次模型复核（慢、花钱） |
| `amnesty_llm_timeout` | `2.0` | 模型复核超时（秒） |

### `config.toml` 必须带 `[plugin]` 节

Runner 从 `[plugin]` 读启停开关和配置版本号，**缺一个就只加载配置管理、不激活业务组件**：

```toml
[plugin]
enabled = true
config_version = "1.0.0"
```

这一节已写进配置模型，Runner 自动生成时天然带它——只有手写配置时才要留意。

### 数据落在哪

统一持久化目录，**不是**插件目录下：

```
<MaiBot>/data/plugins/TommyAAKK.antibait/monitor.jsonl   # 试运行记录
<MaiBot>/data/plugins/TommyAAKK.antibait/tics.json       # 口癖库
```

## 实测数据

在真实群聊里连续运行了 **9 天 / 665 条回复**：

| 指标 | 值 |
|---|---|
| 命中率 | 0.8%（5 / 665） |
| 平均分 | 1.34 |
| live 打回 | 4 次 |
| 误杀 | **0**（修完规则后） |

抓到的真问题：

| 时间 | 分数 | 是什么 |
|---|---|---|
| 10-23 | 101 | 原始 `<message>` 标签整个漏进正文 |
| 10-24 | 100 | 工具调用痕迹 `[glass-meme-lookup]` 漏进正文 |
| 10-24 | 3.3 | 连续附和服软 + 同款颜文字连发 |
| 10-31 | 3.3 | 连续服软（重生成后变成「嘴硬这块你确实没输过」，明显更像人） |

期间修掉的三个误判：881 字周榜被硬规则判 202 分（堆砌按个数不按密度）、
93 字正常回答被判排比（只看分句长度不看结构）、颜文字尾巴 `✧` 被当 emoji 重复计分。

> 这个 bot 本身说话就很短很口语（中位数 34 字），所以八股规则在它身上大多空转。
> 插件对它最实际的价值是**结构卫生检查**——标签残留、工具痕迹这类真 bug。

## 开发

```bash
python tests.py    # 145 项回归测试
python demo.py     # 看实际判定效果
```

不需要装 `maibot_sdk` 就能跑测试和演示（`plugin.py` 里有兼容层）。

| 文件 | 作用 |
|---|---|
| `_manifest.json` | 插件清单（manifest v2） |
| `plugin.py` | Hook + 生命周期 + 配置 + 工具入口 |
| `rules.py` | 遮蔽管线、三档规则、序列判定、机械净化（纯函数） |
| `amnesty.py` | 赦免层：玩梗／复读／回答问题（纯函数） |
| `state.py` | 重生成状态存储 |
| `tics.py` | 口癖候选生成与校验 |
| `monitor.py` | 监控 JSONL 与汇总报告 |
| `tests.py` / `demo.py` | 回归测试 / 效果演示 |

## 已知限制

1. **Hook 超时 6 秒，默认不调 LLM。** 默认全是正则，微秒级。只有 `amnesty_llm=true` 才在 Hook 内调一次（2 秒超时）。
2. **顺序 Hook 无法并行生成**，"择优"本质是"重生成一次再回滚"，第二次 token 照付。
3. **规则只在一台 bot 上验过 665 条**，换 bot 前建议先跑一轮 dry-run。
4. **`echo` 通道分不清「别人说的」和「机器人自己以前说的」**。已做的是"复读源本身是八股就跳过"，但复读自己以前说过的正常话仍会被赦免。
5. **`kao_repeat` 在颜文字多的 bot 上命中率可达 46%**。它单独不会越线，但会和"排比 + 过长"叠加。误判变多时第一个该降它。
6. **WebUI 页面没做**。口癖确认目前是"读草稿 + 手改 `tics.json`"。
